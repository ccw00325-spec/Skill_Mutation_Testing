# Skill Mutation Testing

테스트가 모두 통과하더라도 날짜 경계나 권한 조건을 살짝 바꿨을 때 테스트가 여전히 통과할 수 있습니다. 이 스킬은 그런 변이를 찾아, 어떤 입력과 결과를 검증해야 하는지 AI에게 돌려줍니다.

- JS/TS는 StrykerJS, Java/Kotlin JVM은 PIT를 사용합니다.
- PR에서는 변경된 핵심 로직으로 변이 범위를 좁힙니다. 러너의 커버리지 기반 테스트 선택과 결과 재사용은 별도로 적용합니다.
- 살아남은 변이는 실제 동작을 구분하는 입력으로 재현합니다. 원본에서는 통과하고 변이에서는 실패하는지 확인합니다.

Codex 스킬 경로에 [mutation-testing 폴더](mutation-testing)를 배치한 뒤 다음처럼 요청하세요.

> $mutation-testing 이 PR의 날짜·요금 계산 로직을 검사하고 살아남은 변이를 잡는 테스트를 추가해줘.

[스킬 본문](mutation-testing/SKILL.md) · [도구 설정과 CI](mutation-testing/references/tools.md)

첨부 사례에서 451은 작성된 테스트 수입니다. 변이 550개 중 273개가 검출됐고, 161개가 살아남았으며 116개는 실행되지 않았습니다. 한 프로젝트의 변이 결과이므로 모든 AI 테스트의 실패율로 해석할 수 없습니다.
